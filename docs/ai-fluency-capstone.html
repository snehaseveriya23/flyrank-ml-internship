1. Step-by-Step Protocol: How to Add the Next Case Study

To prevent portfolio stagnation, all future project additions follow an established, frictionless protocol reusing the Week 2 Three-Beat Structure:

The Three-Beat Story Rhythm

  • Beat 1 (The Problem): Concrete operational bottleneck, diagnostic failure mode, and baseline opportunity cost.
  • Beat 2 (What I Did): AI-assisted system architecture, validation design (leakage prevention, OOT splits), and algorithmic trade-offs.
  • Beat 3 (What Came Of It): Empirical benchmark improvements, reproducible artifacts, and automated decision outputs.

The 5-Step Rapid Publication Workflow

  1. Drop Artifacts into Preserved AI Context: Feed code scripts, eval outputs, and README to the customized workspace.
  2. Execute 3-Beat Prompt: Generate a concise case study following the voice kit in under 5 minutes.
  3. Export Figures: Save high-DPI charts to docs/assets/.
  4. Register Route: Place markdown at docs/case-studies/<slug>.md and link from the index.
  5. Commit & Deploy: Push to GitHub main branch for automated live GitHub Pages deployment.

Problem: Search engines frequently shift SERP layouts (introducing AI Overviews and rich snippets) for high-value queries, resulting in unexpected CTR drops on informational pages that otherwise hold top-3 ranks.

Methodology & Solution: Construct a lightweight real-time intent drift detector combining DuckDB temporal telemetry and zero-shot transformer classifiers to flag pages needing snippet/schema redesign before traffic drops.
